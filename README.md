# 쪼개라! 투두리스트

GitHub Pages에서 동작하는 트리형 할 일 앱. 로그인 없이 기존 브라우저 저장을 사용할 수 있고, Google 로그인 시 Firebase의 계정별 저장소로 자동 동기화합니다.

## 동기화와 복구

- 새 기기의 빈 목록을 서버의 삭제 요청으로 취급하지 않습니다.
- 프로젝트·할 일·완료 이벤트를 개별 문서로 저장합니다. 마지막으로 반영한 서버 시각 이후의 변경을 구독하며 삭제도 기록으로 남깁니다.
- 같은 항목의 서로 다른 필드 수정은 합칩니다. 같은 필드의 충돌은 양쪽 내용을 보존하고 사용자 선택을 기다립니다.
- 항목마다 이전 3개 버전을 보관합니다. 서버 규칙이 버전 증가와 복구 기록 유지를 확인합니다.
- `복구 기록`에서 이전 항목을 복구할 수 있습니다. 트리 전체를 한 번에 이전 시점으로 되돌리는 스냅샷 기능은 아닙니다.
- 화면 배치·접힘·실행 중인 타이머·Gist 토큰·SelfTalkie 연결 토큰은 기기별 설정입니다.
- 로그아웃 시 이 기기의 목록은 남습니다. 다른 Google 계정으로 로그인하면 해당 계정의 별도 목록으로 전환합니다.

## 개발

`npm ci`, `npm run build`, `npm test` 순서로 실행합니다. 빌드된 `cloud-bundle.js`도 Pages 배포를 위해 커밋합니다.

규칙 테스트는 Firebase CLI로 `demo-jjogaera` 프로젝트의 Firestore 에뮬레이터를 8180 포트에 실행한 뒤 `npm run test:rules`로 실행합니다. 실제 사용자 데이터에는 테스트를 실행하지 않습니다.

브라우저 통합 테스트는 같은 프로젝트의 Auth 에뮬레이터(9199)도 실행하고 `npm run test:browser`로 실행합니다. Playwright Chromium 설치가 필요하며 `PLAYWRIGHT_CHROME_EXECUTABLE` 환경변수로 설치된 Chrome을 지정할 수도 있습니다. 두 브라우저의 변경 병합, 오프라인 수정, 복구, 550개 항목 전송, 재시작, 계정 전환을 검증합니다.

배포 규칙: `firebase deploy --only firestore:rules --project selftalkie-fd7e7`.

Firebase 웹 설정의 API 키는 앱 식별용 공개 설정입니다. 관리자 자격 증명과 로그인 토큰은 저장소에 넣지 않습니다. 데이터 권한은 `firestore.rules`가 Google 로그인 계정의 UID별로 제한합니다.
